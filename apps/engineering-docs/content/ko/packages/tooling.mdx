## 개요

`@jongminchung/tooling`은 formatter 기본값과 공유 linter 설정을 한곳에서 관리합니다. 설정을 복사하지 않고 작은 override만 선언하는 것이 목표입니다.
Node.js 24 이상에서 사용할 수 있으며 ESM JavaScript 함수 하나와 JSON asset 하나를 공개합니다.

`read:packages` 권한이 있는 classic PAT로 GitHub Packages를 설정하고 package와 Oxfmt peer를 함께 설치합니다.

```ini
@jongminchung:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_PACKAGES_TOKEN}
```

```bash
pnpm add --save-dev @jongminchung/tooling oxfmt oxlint
```

## oxlint

사용하는 Oxlint 설정에서 `./node_modules/@jongminchung/tooling/oxlint.json`을 확장합니다. package root의 안정적인 asset은 `@jongminchung/tooling/oxlint.json` subpath로도 게시되며 type-aware 분석, 미사용 변수, floating promise와 잘못 사용한 promise 검사를 활성화합니다.

## oxfmt

```ts
import { defineOxfmtConfig } from "@jongminchung/tooling/oxfmt";

export default defineOxfmtConfig({
    printWidth: 100,
    ignorePatterns: ["generated/"],
});
```

공개 config와 override 이름은 Oxfmt 공식 타입의 alias입니다. 기본 ignore와 override는 유지되고 호출자의 배열이 뒤에 합쳐집니다. object 형태의 `sortImports`와 `sortPackageJson`은 중첩 기본값과 병합하고 boolean 값은 기본값을 대체합니다.

## 모듈 계약

모든 JavaScript entry point는 ESM `import`로 사용합니다. CommonJS `require()`는 지원하는 패키지 계약에 포함하지 않습니다.

고정 `1.0.0`은 재현 가능한 SemVer release가 아니라 mutable personal snapshot입니다. 교체 게시 후 `pnpm update --force @jongminchung/tooling@1.0.0`을 실행하고 갱신된 lockfile integrity를 반영합니다.

## API

- `defineOxfmtConfig`: formatter 기본값과 override 병합
- `oxlint.json`: 저장소의 기본 linter 설정 공유
