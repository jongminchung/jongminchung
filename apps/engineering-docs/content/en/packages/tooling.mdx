## Overview

`@jongminchung/tooling` centralizes formatter defaults and the shared linter config. Consumers declare small overrides instead of copying configuration.
Node.js 24 or newer is required. The package exposes one ESM JavaScript function and one JSON asset.

Configure GitHub Packages with a classic PAT that has `read:packages`, then install the package and its Oxfmt peer:

```ini
@jongminchung:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_PACKAGES_TOKEN}
```

```bash
pnpm add --save-dev @jongminchung/tooling oxfmt oxlint
```

## oxlint

Extend `./node_modules/@jongminchung/tooling/oxlint.json` from the consuming Oxlint config. The stable root asset is also published through the `@jongminchung/tooling/oxlint.json` package subpath and enables type-aware analysis and checks unused values, floating promises, and misused promises.

## oxfmt

```ts
import { defineOxfmtConfig } from "@jongminchung/tooling/oxfmt";

export default defineOxfmtConfig({
  printWidth: 100,
  ignorePatterns: ["generated/"],
});
```

The public config and override names alias Oxfmt's official types. Base ignore patterns and overrides remain in place, with caller arrays appended. Object `sortImports` and `sortPackageJson` values merge with their shared nested defaults; boolean values replace them.

## Module contract

Use ESM `import` for every JavaScript entry point. CommonJS `require()` is not part of the supported package contract.

The fixed `1.0.0` is a mutable personal snapshot rather than a reproducible SemVer release. After a replacement is published, run `pnpm update --force @jongminchung/tooling@1.0.0` and commit the refreshed lockfile integrity.

## API

- `defineOxfmtConfig`: merge formatter defaults and overrides
- `oxlint.json`: share the repository's base linter configuration
