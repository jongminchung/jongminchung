## 핵심 요약

- **8편의 목표는 2~7편의 측정값으로 단일 구독·복수 구독·상위 요금제의 완료 작업당 총비용을 계산하는 것임**
- **총비용은 월 구독료뿐 아니라 재작업·인계·충돌·대기 때문에 발생한 사람 시간을 포함해야 함**
- **기본 선택은 역할을 실제로 수행하는 최소 구독 수이며 남은 한도를 모두 쓰는 것이 목표가 아님**
- **추가 구독은 한도 도달로 미룬 가치가 그 구독료와 조정 비용을 지속적으로 넘을 때만 정당화됨**
- **이 시리즈의 결론은 공급자 순위가 아니라 매월 유지·상향·해지할 수 있는 재검증 가능한 운영 규칙임**

## 가격표를 완료 작업의 경제성으로 바꿈

- **1편의 월 US$20 비교는 진입 가격을 맞춘 것이며 실제 비용을 끝까지 설명하지 못함**
    - `Google AI Pro`, `ChatGPT Plus`, `Claude Pro`는 비슷한 목록가지만 한도 단위와 포함 서비스가 다름
    - 저장공간·일반 채팅·문서 기능의 개인 가치가 있으면 코딩 비용에 전액 배분하지 않을 수도 있음

- **기본 지표는 품질 조정 완료 작업당 총비용임**

```text
월 총비용 = 구독료 + 재작업 시간가치 + 인계·충돌 시간가치
품질 조정 작업당 비용 = 월 총비용 / 검증 후 수용된 작업 수
유효 사용률 = 실제 사용한 포함 할당량 / 구매한 포함 할당량
```

- **사람 시간가는 개인의 기회비용을 반영해 직접 정함**
    - 정확한 임금 계산이 어렵다면 15분·30분·60분 구간으로만 기록해도 조합 간 차이를 볼 수 있음
    - 시간가를 넣지 않으면 여러 에이전트를 조정하는 숨은 비용이 사라짐

- **공급자 간 할당량은 하나의 토큰 수로 합산하지 않음**
    - 각 제품의 사용률은 자체 표시 단위로 계산함
    - 포트폴리오 전체는 수용 작업 수와 총비용으로만 결합함

## 네 가지 포트폴리오를 같은 기록으로 비교함

- **`단일 핵심 구독`은 월 고정비와 조정 비용이 가장 낮은 기준안임**
    - 일주일 동안 한도에 자주 닿지 않고 수용률이 충분하면 우선 유지함
    - 모델 다양성보다 단순성이 중요한 간헐적 사용자에게 적합할 가능성이 있음

- **`핵심 구독 2개`는 구현과 탐색·리뷰 역할이 실제로 분리될 때 후보가 됨**
    - 두 번째 구독이 독립 완료나 재작업 감소를 만들지 못하면 중복 고정비임
    - 장애 대체 가치가 중요하면 월별 실제 대체 횟수를 별도 기록함

- **`Gemini·Codex·Claude의 약 US$60 조합`은 각 역할이 매주 사용될 때만 검토함**
    - 세 제품을 같은 질문의 답변 투표에 쓰면 사용량과 사람 검토가 함께 늘어남
    - 탐색자·구현자·리뷰어의 산출물이 중복되지 않을 때 처리량 이점이 생길 수 있음

- **`한 공급자의 상위 요금제`는 전환 비용을 줄이면서 한도만 늘릴 수 있는 대안임**
    - 현재 기본 구독의 품질과 워크플로가 충분하고 한도만 반복적으로 막힐 때 적합함
    - 제품별 가격·배수·추가 크레딧 정책은 자주 바뀌므로 결제 직전 공식 페이지를 다시 확인해야 함[^codex-pricing][^claude-plan][^gemini-pricing]

| 조합     | 유리할 수 있는 조건           | 주요 위험                      |
| -------- | ----------------------------- | ------------------------------ |
| 핵심 1개 | 한도 여유와 높은 완료율       | 공급자 장애와 특정 작업 약점   |
| 핵심 2개 | 역할 분리 또는 실질적 대체    | 전환·인계 비용                 |
| 핵심 3개 | 매주 세 역할이 모두 필요함    | 중복 탐색과 낮은 사용률        |
| 상위 1개 | 품질은 충분하고 한도만 병목임 | 모델 다양성 감소와 높은 고정비 |

## 추가와 상향은 회수 가능한 가치로 판정함

- **추가 구독의 손익분기점은 그 구독이 없어서 미룬 작업 가치로 계산함**
    - `추가 월비용 < 새로 수용된 작업 가치 + 줄어든 재작업 가치`일 때 후보가 됨
    - 한도에 닿았다는 사실만으로는 추가 구독이 더 나은 완료율을 낸다는 보장이 없음

- **상위 요금제는 세 조건이 함께 맞을 때 검토함**
    - 현재 구독의 한도 때문에 가치 있는 작업이 월 두 번 이상 중단됨
    - 컨텍스트·세션·도구 출력·라우팅 최적화를 이미 적용함
    - 상향 비용보다 지연과 인계 비용의 월 합계가 큼

- **위 횟수와 임계값은 공급자 공식 기준이 아니라 작성자의 시작 규칙임**
    - 업무 가치가 큰 장애 대응은 한 번의 중단도 상향을 정당화할 수 있음
    - 취미 프로젝트는 여러 번 멈춰도 기다리는 편이 경제적일 수 있음

## 유지와 해지 규칙을 미리 정함

- **구독은 결제일 직전의 기분이 아니라 두 결제 주기의 기록으로 평가함**
    - 수용 작업 수, 유효 사용률, 대체 횟수, 재작업 감소, 조정 시간을 확인함
    - 새 제품을 배우는 첫 달은 학습 비용을 별도 표기함

- **작성자의 기본 해지 후보는 두 달 연속 사용률 25% 미만이면서 고유 역할이 없는 구독임**
    - 25%는 보편적 경제 법칙이 아니라 잊힌 구독을 찾기 위한 경보값임
    - 비상 대체·개인 저장공간·일반 채팅 가치가 있으면 그 가치를 명시하고 유지할 수 있음

- **품질이 낮은데 사용률이 높은 구독도 유지할 이유가 되지 않음**
    - 재시도 때문에 한도를 많이 쓴 경우는 높은 활용이 아니라 높은 실패 비용임
    - 수용 작업당 비용과 재작업 시간을 우선함

- **API 키 금지 조건이 바뀌면 별도 실험으로 다시 시작함**
    - `Z.ai GLM Coding Plan`과 `OpenCode Go`를 키 기반 게이트웨이로 추가하면 인증·약관·한도 단위가 달라짐
    - 기존 무키 실험과 같은 표에 섞지 말고 새 기준선을 만들어야 함

## 시리즈 전체의 절감 효과를 감사함

- **2편의 기준선과 7편의 최종 운영 기간을 같은 작업 유형으로 비교함**
    - 완료 작업당 공급자 내부 소진량 중앙값을 비교함
    - 수용률·테스트 통과율·재작업·사람 조정 시간을 함께 비교함
    - 모델이나 한도 정책이 바뀐 기간은 별도 구간으로 나눔

- **절감 주장을 공개하려면 원자료와 해석의 경계를 남겨야 함**
    - 공식 가격·한도는 확인 날짜와 각주를 기록함
    - 15%·20%·25% 같은 임계값은 작성자의 운영 판단임을 표시함
    - 다른 저장소와 사용자에게 같은 결과가 보장되지 않는 한계를 명시함

- **최종 성공은 더 많은 구독이 아니라 더 적은 낭비로 같은 품질을 낸 상태임**
    - 한 개 구독으로 결론 나도 시리즈의 최적화 목표를 달성한 것임
    - 여러 구독이 남는다면 각각 제거했을 때 잃는 고유 역할을 설명할 수 있어야 함

## 결론과 실행 제안

- **간헐적 사용자는 핵심 구독 한 개와 2편의 측정표로 시작하는 구성이 적절함**
- **매일 한 저장소에서 일하는 사용자는 기본 구독의 한도 최적화 뒤 두 번째 역할 구독 또는 상위 요금제 중 하나만 시험해야 함**
- **여러 저장소와 병렬 작업이 있는 사용자는 worktree·한 명의 쓰기 소유자·조정 시간 기록을 전제로 복수 구독을 검토해야 함**
- **매월 결제 3일 전에 `유지·상향·해지` 중 하나를 기록하고, 공식 가격과 한도는 분기마다 재검증해야 함**
