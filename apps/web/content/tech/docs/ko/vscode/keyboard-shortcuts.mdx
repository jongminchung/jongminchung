## 먼저 외울 작업

처음에는 Command Palette, Quick Open, 정의·사용처, Rename, Quick Fix를 익힙니다. 파일 탐색기를 반복해서 여는 대신 호출 경로를 따라가며 작은 변경을 완성하는 데 사용합니다. 단축키는 확장을 설치하는 명령이 아닙니다. F12·F2 같은 언어 기능은 해당 언어 서비스가 준비되어야 동작합니다.

## 운영체제별 기본 단축키

기본 US 키보드 기준이며 확인일은 2026-09-06입니다. `→`는 앞 조합을 누른 뒤 다음 조합을 누르는 순차 입력입니다. macOS의 F키에는 Fn이 필요할 수 있습니다. **Linux의 Peek Definition·Go Back·Format Document는 Windows와 다릅니다.**

## 동작하지 않는 키 찾기

Keyboard Shortcuts에서 명령을 검색하고 키 기록 버튼으로 실제 입력을 확인합니다. 같은 키의 다른 할당과 `when` 조건을 비교합니다. 터미널에 초점이 있으면 편집기 명령과 결과가 다를 수 있고, OS·입력기가 키를 먼저 사용할 수도 있습니다. `Developer: Toggle Keyboard Shortcuts Troubleshooting`으로 입력 해석 로그를 확인한 뒤 다시 꺼 둡니다. [키 바인딩 진단](https://code.visualstudio.com/docs/configure/keybindings)

IntelliJ·Vim 키맵을 사용한다면 이 표보다 현재 Keyboard Shortcuts 표시를 우선합니다. 팀 저장소에 개인 키맵을 강제하기보다 Profile에 보관합니다.

## 5분 반복 실습

1. Quick Open에서 실제 파일 이름 뒤에 `:42`를 붙여 줄로 이동합니다.
2. 함수의 정의와 사용처를 확인하고 Go Back으로 복귀합니다.
3. 함수 이름을 F2로 변경하고 테스트를 실행합니다. Ctrl+D는 텍스트 다중 선택이므로 심볼 Rename을 대신하지 않습니다.
4. 중단점을 설정하고 F5 → F10 → F11 → Shift+F11 순서로 변수 변화를 봅니다. 함수 호출 줄에서 실습하며 비동기·외부 코드는 디버거 설정에 따라 건너뛸 수 있습니다.
5. Format Document 후 diff를 확인합니다. 이 명령은 선택된 formatter를 실행하며 타입 검사나 모든 lint 규칙을 해결하지 않습니다.

테스트 실행·개별 테스트 디버깅·import 정리는 언어 확장의 명령 또는 CodeLens에서 시작합니다. 모든 언어에 같은 기본 단축키가 있다고 가정하지 않습니다. [언어별 확장 구성](/ko/docs/vscode/extensions-and-profiles)과 [프로젝트 탐색 실습](/ko/docs/vscode/workspace-and-navigation)으로 이어갑니다.
