## Key facts

- **`rke2spray` owns hosts, RKE2, cluster-foundation add-ons, and the Argo CD bootstrap**
- **The GitOps repository owns platform, data, observability, and storage resources after the root Application**
- **Cluster-specific RKE2, CNI, topology, and network values are declared under `inventory/<cluster>/`**
- **GitOps verifies 15 Argo CD `Application` resources including the root `bootstrap`, and `301Gi` of application PVC requests**
- **Telemetry follows two persistent queues before ClickHouse, then a ClickHouse-owned `ZSTD(3)` and SeaweedFS S3 lifecycle**
- **The NFS endpoint, external L4 load balancer, and absence of external backups define the current availability and recovery boundaries**

## 2. Architecture constraints

- **The Kubernetes distribution is fixed at `RKE2 v1.36.3+rke2r1`, with `Cilium 1.20.1` as its CNI**
  - `jamie-kr-gitops/ansible/rke2spray.rev` selects the verified `rke2spray` commit
- **Control-plane API and Gateway traffic depend on a stable external TCP load balancer outside both repositories**
  - A server must leave LB backend pools before node removal begins
- **Persistent workloads currently share one managed NFS endpoint**
  - `durable-rwo` and replica spreading do not isolate an NFS service failure or data loss
- **Plaintext secrets are not stored in Git**
  - Host bootstrap values use Ansible Vault, while Kubernetes application values use the SOPS and age boundary

## 4. The solution strategy switches reconciliation engines at API readiness

- **`rke2spray` reconciles hosts and RKE2 desired state before the Kubernetes API exists**
  - It validates Kubespray-shaped inventory and translates it into the RKE2 server and agent lifecycle
- **The bootstrap gate turns API creation and platform readiness into executable conditions**
  - It checks nodes, Cilium, CoreDNS, Gateway API, cert-manager, and NFS CSI readiness
- **Argo CD continuously reconciles application desired state after API creation**
  - The root Application creates role-scoped child Applications and sync waves
- **Both engines consume one environment release without concurrently owning the same resource**
  - This boundary is the condition for safely combining Ansible IaC and GitOps in one repository

- **These targets are defined by the repository-root `Makefile`**

| Target                                                 | Main inputs                        | Behavior                                                     |
| ------------------------------------------------------ | ---------------------------------- | ------------------------------------------------------------ |
| `make check`                                           | Development tools                  | Run lint, unit, contract, parity, and syntax checks          |
| `make inventory-graph`                                 | `INVENTORY`, `VAULT_PASSWORD_FILE` | Print the resolved inventory graph                           |
| `make inventory-vault-check`                           | `INVENTORY`, `VAULT_PASSWORD_FILE` | Check Vault inputs and file mode without SSH                 |
| `make inventory-preflight`                             | Inventory and environment          | Check live topology, ports, and storage prerequisites        |
| `make cluster-converge`                                | Inventory and Vault                | Run `cluster.yml`                                            |
| `make cluster-health`                                  | Inventory and Vault                | Inspect API, Node, etcd, and service health                  |
| `make cluster-scale NODE=<node>`                       | Worker name                        | Reconcile one selected worker with `scale.yml`               |
| `make cluster-add-server NODE=<node>`                  | Server name                        | Reconcile one server with `cluster.yml --limit`              |
| `make cluster-upgrade`                                 | Updated version lock               | Cordon, drain, change release, and verify readiness          |
| `make cluster-snapshot SNAPSHOT=<name>`                | Snapshot name                      | Create a manual embedded-etcd snapshot                       |
| `make cluster-recover SERVER=<server> SNAPSHOT=<path>` | Server and absolute path           | Restore the control plane after checksum validation          |
| `make cluster-remove-node NODE=<node>`                 | Node and LB-removal confirmation   | Remove LB, etcd, Kubernetes Node, and RKE2 state             |
| `make cluster-rotate-certificates`                     | Inventory and Vault                | Rotate RKE2 certificates                                     |
| `make gateway-access`                                  | Inventory and Vault                | Inspect and verify the Gateway access contract               |
| `make gitops-bootstrap`                                | GitOps inputs and Vault            | Apply Argo CD and the root Application after readiness gates |
| `make gitops-integration`                              | `GITOPS_INTEGRATION_SCRIPT`        | Run a GitOps integration script on the bootstrap server      |

- **Cluster access does not copy a long-lived kubeconfig into the environment repository**
  - `kubeconfig_localhost: false` and `kubectl_localhost: false` keep Ansible-controller artifacts disabled
  - Read-only checks should run the bundled `kubectl` remotely through `scripts/run_with_ssh_jump.py`
  - Local integration tests use `operations/with-cluster-kubeconfig.sh`, which retrieves `/etc/rancher/rke2/rke2.yaml` into `XDG_RUNTIME_DIR`, opens a loopback SSH tunnel, verifies `/readyz`, and removes the credential on exit
  - `operations/cluster-kubeconfig.md` is the detailed issuance, validation, cleanup, and incident-response runbook

- **`cluster-reset`, `cluster-recover`, `cluster-remove-node`, add-on pruning, and failure probes can destroy or interrupt state**
  - Each target requires a bounded target, confirmation value, or opt-in environment variable
  - Server removal requires prior removal from external LB backends on ports `80`, `443`, `6443`, and `9345`
  - Off-host snapshot transfer and retention are outside the `rke2spray` contract

## 8. Cross-cutting observability and storage concepts

### Authenticated durable ingestion

<ObservabilityPipelineFlow locale="en" />

- **Every telemetry signal enters through the two-replica OTel Gateway**
  - Agent, Cluster Collector, and application OTLP traffic share the same batch, infinite retry, and `1Gi` PVC queue boundary
  - The Gateway authenticates to ClickStack ingestion with the protected HyperDX API credential
- **ClickStack ingestion is a two-replica StatefulSet with a second persistent queue boundary**
  - Both ClickHouse exporters use `file_storage`, queue size `8192`, and infinite retry
  - A ClickHouse outage after Gateway delivery therefore remains recoverable from the ingestion PVC queue
- **Resource identity preserves application semantics**
  - Collectors add `k8s.cluster.name=jamie-kr` and their platform role
  - They do not overwrite an SDK-provided `service.namespace`
- **NetworkPolicies limit OTLP and S3 ingress**
  - Only the OTel Gateway and HyperDX can reach ClickStack ingestion ports
  - Only ClickHouse can reach the private S3 data port, while the Cluster Collector can reach its metrics port

### Compression and cold-storage lifecycle

<TelemetryStorageLifecycle locale="en" />

- **All nine ClickStack telemetry tables use the `hot_cold` ClickHouse storage policy**
  - New replicated parts start on the `default` hot volume backed by `durable-rwo`
  - Eligible parts are recompressed with `CODEC(ZSTD(3))` after two days
  - Parts move to the `cold_s3` volume after three days
  - ClickHouse deletes table parts and their owned S3 objects after 14 days
- **ClickHouse is the single lifecycle owner**
  - SeaweedFS does not apply an independent bucket TTL that could remove objects before ClickHouse metadata changes
  - The PostSync retention Job creates the private bucket idempotently before applying table settings and TTL expressions
- **Cold storage reduces hot PVC pressure but is not a backup**
  - ClickHouse replicas use separate S3 prefixes and still depend on the same SeaweedFS and NFS failure domain
  - Deletion, corruption, or loss of the shared storage layer is not recoverable from Git

## 9. Architecture decisions for telemetry retention

| Decision                        | Reason                                                                            | Consequence                                                                        |
| ------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Two persistent queue boundaries | Preserve accepted telemetry across Gateway, ingestion, or ClickHouse restarts     | Adds two Gateway and two ingestion PVCs                                            |
| Dedicated private S3 gateway    | Isolate ClickHouse credentials and traffic from the public S3 route               | Adds two stateless gateway replicas and a PDB                                      |
| ClickHouse-owned TTL            | Keep table metadata and object deletion in one state machine                      | SeaweedFS bucket lifecycle must remain disabled for this bucket                    |
| Recompress before cold movement | Lower long-term object size without applying maximum compression to hot ingestion | Background merges consume CPU after two days                                       |
| Fourteen-day deletion           | Bound telemetry storage growth                                                    | Older telemetry requires a separate backup design if retention requirements change |

### Live-cluster verification

- **`tests/integration/verify.sh` defines the following completion state**
  - All 15 Argo CD Applications report `Synced` and `Healthy`
  - Stateful and stateless Application prune and finalizer policies match
  - Three-replica workloads are `Ready` on three distinct workers
  - Services excluded from public exposure remain `ClusterIP`
  - No Pod is Pending and every Node root filesystem remains below `60%` usage
  - `durable-rwo` uses `nfs.csi.k8s.io`, `Immediate`, `Retain`, and `onDelete=retain`
  - All target PVCs use `durable-rwo` and total `301Gi`
  - ClickStack ingestion and the private S3 gateway each have two ready replicas on distinct workers
  - Collector self-metrics include the `otelcol_*` family in ClickHouse
  - All nine telemetry tables use `hot_cold`, `ZSTD(3)`, three-day cold movement, and fourteen-day deletion
  - The `cold_s3` disk is visible in `system.disks`
  - Gateway `HTTPRoute` resources report `Accepted=True` and `ResolvedRefs=True`

- **Verification that writes or deletes state requires an explicit opt-in variable**
  - The NFS performance gate requires `RUN_NFS_PERFORMANCE_GATE=true`
  - The database gate requires `RUN_NFS_DATABASE_GATE=true`
  - Tri-signal telemetry generation requires `RUN_TELEMETRY_E2E=true`
  - Workload disruption checks require `RUN_DISRUPTIVE_TESTS=true`

- **The tri-signal E2E gate proves the complete write path**
  - A digest-pinned `telemetrygen` Pod emits logs, metrics, and traces with a unique `service.name`
  - Queries require all three signal families and `k8s.cluster.name=jamie-kr` to appear in ClickHouse
  - Generator Pods are removed after the test, while their small telemetry payload follows the normal retention lifecycle

## 11. Risks and recovery boundaries

| Boundary                                | Current contract                                                     |
| --------------------------------------- | -------------------------------------------------------------------- |
| Single-node failure                     | Control-plane and major stateful-workload replicas provide tolerance |
| External LB failure                     | Infrastructure failure domain outside both repositories              |
| NFS endpoint failure                    | Can affect every NFS-backed stateful workload                        |
| SeaweedFS S3 cold tier                  | Capacity tier inside the same platform failure boundary, not backup  |
| PVC deletion                            | `Retain` and stateful `prune: false` restrict automatic deletion     |
| Complete NFS loss                       | Not recoverable from repository assets alone                         |
| PostgreSQL backup and PITR              | Out of scope                                                         |
| Existing PVC and legacy workloads       | Automatic migration is out of scope                                  |
| Off-host etcd snapshot retention        | Outside the `rke2spray` contract                                     |
| Argo CD SSO and operator RBAC hardening | Out of scope                                                         |
| Temporary admin kubeconfig              | Cluster-admin credential limited to private runtime and SSH tunnel   |
