# 기술 스택과 공식 문서

이 문서는 `plugins/go-lsp`를 제외한 pnpm 모노레포의 기반 기술과 외부 직접 의존성을
관리한다. 버전은 `.node-version`, 루트 `package.json`, `pnpm-workspace.yaml`의 catalog와 각
workspace manifest를 기준으로 한다.

외부 직접 의존성을 runtime과 dev 구분 없이 모두 포함한다. 내부
`@jongminchung/*`, 선언만 제공하는 `@types/*`, lockfile에만 존재하는 전이 의존성, vendor
material의 예제 언어·라이브러리는 제외한다.

## 표 읽는 법

사용 위치는 다음 약칭을 사용한다.

| 약칭      | Workspace                        |
| --------- | -------------------------------- |
| `root`    | 저장소 루트                      |
| `docs`    | `@jongminchung/engineering-docs` |
| `git`     | `@jongminchung/git-client`       |
| `readme`  | `@jongminchung/readme`           |
| `icon`    | `@jongminchung/icon`             |
| `tooling` | `@jongminchung/tooling`          |
| `ui`      | `@jongminchung/ui`               |

`runtime`은 배포 코드가 직접 import하는 의존성이고 `dev`는 빌드·검사·패키징에 쓰는
의존성이다. 공식 전용 문서가 없으면 package maintainer의 공식 저장소 README를 연결한다.

## 수동 갱신 규칙

외부 직접 의존성을 추가·삭제·변경할 때 이 문서를 같은 변경에서 갱신한다.

1. 모든 `package.json`의 `dependencies`, `devDependencies`, `peerDependencies`를 확인한다.
2. 내부 `@jongminchung/*`와 `@types/*`를 제외한 package가 위 표에 한 번 이상 있는지 대조한다.
3. 버전은 workspace manifest의 `catalog:` 표기가 아니라 `pnpm-workspace.yaml`의 실제 catalog
   값을 기록한다.
4. 사용 위치와 runtime·dev 역할을 갱신한다.
5. 공식 전용 문서를 우선하고, 없으면 maintainer의 공식 source repository를 연결한다.
6. major 업데이트에서는 version별 문서, migration guide와 release note를 함께 검토한다.
7. link redirect와 저장소 이전 여부를 확인한 뒤 `pnpm run fmt:check`와 `git diff --check`를
   실행한다.
